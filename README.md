# Текстом

Мобильный сайт для чтения YouTube: ссылка или поиск → субтитры с тайм-кодами. Посетителям не нужен Google-аккаунт или API-ключ.

## Что работает

- Поиск 24 видео, переход из результатов на канал.
- Ссылки youtube.com/watch, youtu.be, Shorts, live и ID видео.
- Авторские и автоматические субтитры, выбор языка (по умолчанию ru → en → остальные).
- Поиск внутри текста, тайм-коды со ссылкой на момент видео, копирование, TXT и ссылка на страницу чтения.
- Сохранённые видео с кешем загруженного транскрипта и подписки на каналы в localStorage.
- Видео канала с постраничной загрузкой; добавление канала по @handle или ссылке.
- Экспорт/импорт библиотеки JSON для переноса между телефоном и компьютером. Автосинхронизации нет.

На главной есть быстрый переход в Jerrycs2 (`UCKaEoPORRt-JfrbWaU76GXQ`, канал проверен реальным поиском) и поиск разборов CS2 на русском. Это стартовые точки, а не рейтинг. Другие каналы можно добавить по ссылке. Рекомендательная система пока не реализована.

## Быстрый запуск (Windows, Python 3.11+)

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Интерфейс и API обслуживаются одним процессом. Загрузка аудио и видео не выполняется.

Повторный запуск: `./start.ps1`. Для доступа с телефона в одной Wi-Fi-сети: `./start.ps1 -Lan` и открыть `http://<LAN-IP-компьютера>:8000`. Компьютер должен быть включён; Windows Firewall должен разрешать входящие подключения Python в частной сети. Этот режим не публикует сайт в интернете.

## Массовая выгрузка на ПК без кредитов

Дважды щёлкнуть `bulk-export.cmd`. В открывшемся окне вставить ссылку на канал, `@имя` или список ссылок на видео (по одной на строке), выбрать папку и нажать «Скачать тексты». Используются Python и зависимости проекта; на этом компьютере они уже установлены. На другом ПК сначала требуется обычная установка из раздела «Быстрый запуск».

Программа последовательно обходит вкладки видео, Shorts и трансляций канала без ограничения первыми 24 роликами. Сохраняет отдельные TXT и JSON, общий `all-transcripts.txt` с тайм-кодами и `report.json` с пропусками. При повторной выгрузке в ту же папку использует уже сохранённые JSON. При остановке сохраняет готовые тексты. Закрывать окно следует после завершения остановки.

Отдельные тексты лежат в `texts/<тема>/` и называются `<тема> — <название видео> [ID].txt`. Название и тема также указаны внутри TXT и в отчёте. ID предотвращает перезапись роликов с одинаковыми названиями, запрещённые в Windows символы заменяются пробелами. Для отдельных ссылок название запрашивается у YouTube и сохраняется в кеше.

Поле «Тема» позволяет выбрать категорию или вписать свою для всей выгрузки. Режим «Автоматически» группирует по ключевым словам названия, затем первых фрагментов текста: разборы, тактика и гранаты, аим и движение, настройки, киберспорт и новости, программирование или другие темы. Это простая бесплатная группировка, она может ошибаться. Повторный запуск в старую папку создаёт именованные тексты из кеша; прежние файлы сохраняются.

Этот режим обращается к YouTube напрямую с ПК, никогда не использует `SUPADATA_API_KEY` и не расходует кредиты. Видео без доступных субтитров пропускаются; распознавания аудио нет. YouTube может ограничивать массовые запросы и с домашнего IP: при блокировке выгрузка останавливается. Это локальная утилита, а сайт на Render работает независимо от неё. В Supadata нет режима «весь канал за один кредит» — отдельные запросы субтитров тарифицируются отдельно.

## Публикация на GitHub Pages

GitHub Pages раздаёт только HTML/CSS/JS, поэтому API нужно разместить отдельно. Публикация одного `web/` не обеспечивает поиск и получение субтитров без сервера.

Готовое развёртывание Python API: [Deploy to Render](https://render.com/deploy?repo=https://github.com/Weij33t/utscraber). Blueprint выбирает план `free`, разрешает CORS для `https://weij33t.github.io` и включает обновление API при пуше в `main`. Прокси не обязателен при создании сервиса; `YOUTUBE_PROXY` можно добавить позже в панели при блокировке со стороны YouTube. Создание сервиса требует входа в собственный аккаунт Render. После запуска нужно проверить **не только `/api/health`, но и реальный поиск и транскрипт** с IP хостинга.

1. Развернуть Dockerfile на VPS или создать Render Blueprint по `render.yaml` (можно обслуживать весь сайт непосредственно с API).
2. Задать `ALLOWED_ORIGINS=https://<owner>.github.io` на сервере (без пути репозитория). Для нескольких origins использовать запятую.
3. В Settings → Secrets and variables → Actions → Variables задать `TEKSTOM_API=https://<api-domain>`. Это публичный адрес, без ключей и паролей. Сборка записывает его в `dist/config.js`. Посетитель также может задать API через настройки интерфейса. Без переменной интерфейс публикуется с сообщением о необходимости подключить API.
4. Загрузить проект в репозиторий GitHub в ветку `main`.
5. В Settings → Pages → Build and deployment выбрать **GitHub Actions**. Каждый `git push origin main` запускает `Publish GitHub Pages`: проверка JS → тесты фронтенда и API → сборка → публикация `dist/`. Если проверка падает, новая версия не публикуется. Pull request в `main` запускает только проверки. Возможен ручной запуск через Actions → Run workflow.
6. Проверить `https://<owner>.github.io/<repository>/` на телефоне, выполнить реальный поиск и открыть видео с субтитрами.

На бесплатном Render возможны холодный старт и блокировка IP со стороны YouTube. Стоимость и условия выбранного хостинга проверь перед созданием сервиса.

Локальные коммиты попадают на сайт после отправки в GitHub (`git push`). После изменения `TEKSTOM_API` перезапусти workflow: переменная применяется при сборке. `version.json` на сайте содержит SHA опубликованного коммита. Пайплайн GitHub Pages публикует интерфейс; обновление отдельного API настраивается у его хостинга. Перед публикацией дополнительно проверяются доступность API и CORS. Без рабочего подключения новая версия не публикуется.

### VPS / Docker

```sh
docker build -t tekstom .
docker run --rm -p 8000:8000 -e ALLOWED_ORIGINS=https://<owner>.github.io tekstom
```

Настроить HTTPS через reverse proxy. Внешний сайт GitHub Pages не сможет обратиться к локальному HTTP-серверу по `127.0.0.1` телефона: это сам телефон. Для локального использования с телефона можно открыть сервер в домашней сети, запустив uvicorn с `--host 0.0.0.0`. Интерфейс и API на одном origin работают без дополнительных CORS-настроек.

### Ограничения YouTube

Для Render с заблокированным YouTube IP поддерживается внешний сервис Supadata: создать бесплатный аккаунт на [dash.supadata.ai](https://dash.supadata.ai/), скопировать API-ключ в Render → Environment → `SUPADATA_API_KEY` и сохранить с перезапуском сервиса. Ключ хранится только на сервере. При его наличии транскрипты запрашиваются через Supadata, а поиск и каналы остаются прямыми запросами YouTube. Это работает без включённого домашнего компьютера, локальных команд и прокси.

По [тарифу Supadata](https://supadata.ai/pricing) на момент настройки бесплатный план даёт 100 кредитов в месяц без карты. Запрос готовых субтитров расходует 1 кредит; повторные запросы и переключение языка могут расходовать кредиты. Сервер кеширует текст на час (кеш очищается при перезапуске). Установлен `mode=native`: платное по минутам AI-распознавание не запускается. При исчерпании квоты сайт показывает ошибку лимита. В `/api/health` поле `transcriptProvider` показывает выбранный источник, но не подтверждает действительность ключа — для этого нужен реальный запрос транскрипта.

Используется [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api) для `timedtext` и внутренних данных YouTube, а [yt-dlp](https://github.com/yt-dlp/yt-dlp) — для поиска и каналов. Это не официальный стабильный Transcript API. Библиотеки могут требовать обновлений при изменении YouTube. Нет гарантии доступности конкретного ролика.

- Если субтитров нет, текст получить нельзя: распознавание аудио не подключено.
- Закрытые, платные и ограниченные по возрасту ролики не поддерживаются.
- YouTube блокирует IP, особенно облачные. API возвращает 503 с объяснением. При необходимости задать `YOUTUBE_PROXY=http://user:password@host:port` **только на сервере**. Не публиковать прокси и cookies в репозитории. Пользовательский Google-аккаунт не используется.
- API имеет кеш (10 минут для поиска и каналов, час для текста; максимум 256 записей) и ограничивает число одновременных запросов к YouTube тремя. Для широкого публичного использования нужны rate limiting на reverse proxy и мониторинг. Это версия для личного использования.
- Подписки в приложении независимы от подписок YouTube. Удаление данных браузера удаляет локальную библиотеку; используй экспорт.

## Проверка

```powershell
.venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest -q
npm test
npm run check
```

Автотесты API используют подменённые ответы YouTube: они проверяют обработку ссылок, языки, кеш, ошибки и пагинацию, но не доказывают доступность YouTube с IP выбранного хостинга. Реальный поиск и транскрипт необходимо проверять после размещения.
